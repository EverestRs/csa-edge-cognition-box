# 边缘侧 AI 迁移方案（v3.0 — 算法主体 · 最小硬件壳）

> 版本：v3.0 ｜ 日期：2026-09-26
> v3.0 变更（价值转向）：目标从"工程完备的边缘移植"改为**"算法主体 + 最小硬件壳"**——砍掉为稳健性服务、但 5 分钟演示看不见的一切投入（多路并发/24h 烤机/INT8 精度全表/ESP32 执行链/内存预算苦战），把所有工时转投**算法创新性与可展示性**。
> 关联文档：`AIoT_COMPETITION.md`（参赛方案，本迁移蓝本的演示化版本）、`ARCH.md`、`TECHNICAL_REPORT.md`、`WEAKNESS_AUDIT.md`、`TODO_PHASE2.md`
> 约束不变：全本地（禁云端 API）、无 Docker、单块 Atlas 200I DK A2。

## 1. 核心转向：把 VLM 从"质量裁判"改成"语言接口"

这是整份方案重构的支点，也是 v2.x 与 v3.0 的本质区别。

v2.x 让边缘 VLM 干它不擅长的事——细粒度视觉判定（灰区复核、开放词汇看图），这押着两座悬崖：**质量悬崖**（7B 对 <150px 已 50/50，小模型只会更差，见 WEAKNESS_AUDIT）+ **工具链悬崖**（CANN/llama.cpp 实测路径集中在 Qwen-VL 家族，多模态在昇腾 310B 支持度未知 = G3/G4 命门）。

v3.0 让语言模型只做它擅长的、且"差一点照样好看"的事：

```
视觉判定 → 确定性感知层（NPU OM + crop 多分类器 + 规则引擎）  毫秒级、可复现、无悬崖
语言/交互 → 微型文本 LLM（Qwen2.5-1.5B 级，纯文本，非多模态）  解析指令/合成旁白/答问/讲解
```

三个直接后果：
1. **命门出清**：纯文本小模型在昇腾上有成熟路径（llama.cpp CANN 后端 / MindSpore / MindIE），多模态 G3/G4 降级为可选 stretch，不再是主线阻塞；
2. **4GB 从苦战变从容**：文本 1.5B Q4 ≈ ~1GB（vs 多模态 2B 峰值 2.2GB），v2.1 那套"交替独占加载腾内存"的苦活整个不再需要——**内存不再是方案瓶颈**；
3. **叙事反而更硬**："不是把大模型硬塞进边缘盒，而是让语言只做语言、确定性小模型守住视觉，在 8TOPS 国产单芯片上各司其职"——这是真·架构创新，正面回击"是不是只是塞了个 7B"。

## 2. 四层算法架构

```
┌── 边缘推理盒 Atlas 200I DK A2（单盒 · ≤20W · 全本地 · 无云）───────┐
│ L1 确定性感知层   RTSP/USB 视频 →VDEC硬解→ YOLOv8n OM@NPU →          │
│                    ByteTrack → ViTPose(OM/CPU)133点 → PoseClassifier │
│                    → Crop多分类器(M01吸烟/H03跌倒/挥手/鼓掌/打电话…)  │
│                    → 行为规则(S01徘徊/S02禁区)                        │
│ L2 分层决策        三级置信度分流（无VLM版）：高→采纳 / 灰区→crop仲裁  │
│                    / 低→SlowFast兜底；C2 时序平滑                      │
│ L3 语言交互层      Qwen2.5-1.5B(纯文本)：一句话布控解析·感知事实→      │
│                    自然语言旁白合成·场景记忆问答·规则执行语义          │
│ L4 可解释可视化    复核链路字幕流（置信度0.6→crop判非吸烟→翻案→Normal） │
│                    点谁说谁旁白·实时底牌数据（fps/内存/npu-smi功耗）   │
│ ── 服务 ──  FastAPI+WebSocket :8000 ｜ Mosquitto Broker(本机) ｜      │
│            Streamlit 看板(浏览器访问)                                  │
└───────────────────────────────────────────────────────────────────────┘
        摄像头即传感器(数据采集) · MQTT(网络通信) · 看板(IoT应用)
```

摄像头 + 单盒 + MQTT + 看板构成**最小合规 AIoT 壳**，仍满足赛题"数据采集/网络通信/边缘 AI 推理"三能力——只是把工时从执行硬件搬到了算法。

## 3. 硬件事实与可行性（算法主体版）

| 项 | Atlas 200I DK A2（310B） |
|---|---|
| AI 算力 | 8 TOPS INT8 / 4 TFLOPS FP16 |
| CPU | 4× Cortex-A55 弱核（感知编排瓶颈，靠 VDEC+步长缓解）|
| 内存 | **4GB/8GB 两版；算法主体版下 4GB 也能跑**（文本 1.5B ~1GB，无多模态苦战）|
| 视频 | VDEC/VPU 硬解（H.264/265）——CPU 压力关键解药，仍是必测前置 G2 |
| 软件栈 | CANN + ATC(ONNX→OM) + MindSpore；**文本 LLM 有成熟路径**（多模态转 stretch）|

### 3.1 Go/No-Go 验证线（M0，仍关键但风险大降）

- **G1（内存）**：`cat /proc/meminfo` 确认 4GB/8GB——**不再是"有无 VLM"的分水岭**，只影响能否再挂一个 stretch 多模态档；
- **G2（VDEC 硬解）**：昇腾 VPU 硬解 1080p@25fps、CPU <40%——**仍是单盒成立与否的第一前置**（不通则退双盒，见附录）；
- **G3（感知上 NPU）**：YOLOv8n ATC→OM 跑通；ViTPose 可行性（退 CPU 或 17 点）；
- **G4（crop 主闸）**：crop 多分类器 A55 CPU/OM 单帧 ≤20ms——**视觉判定的质量与速度全靠它，是新的算法承重件**；
- **G5（文本 LLM）**：Qwen2.5-1.5B 在 CANN 跑通、tok/s 实测（解析一句话 ≤2s）；
- **G6（GRU 上 A55）**：PoseClassifier ONNX ≤50ms。

> 与 v2.x 最大区别：原 G3/G4 多模态命门已不在关键路径上。

## 4. 分层迁移设计

### 4.1 感知层 @ A55 + NPU + VDEC（不变的核心）
- 视频：RTSP/本地 → **VDEC 硬解**（绕开 CPU 软解）→ 帧缓冲降采样；`VideoStream` 加 VDEC 后端，保留软解回退；
- 检测：YOLOv8n INT8 → ATC → OM @ NPU（昇腾官方有 YOLO 样例，风险低）；
- 姿态：ViTPose-S INT8（OM 优先，退 CPU，最后 YOLOv8n-Pose 17 点重训）；
- 行为 GRU：PoseClassifier ONNX @ A55；
- 跟踪/规则/三级决策：纯 Python @ A55，靠步长降帧 + 向量化；三级决策改无 VLM 版（阈值上调 + crop 仲裁 + SlowFast 兜底 + C2 平滑）。

### 4.2 Crop 多分类器（新的算法承重件，M0 后立即启动）
- **职责升级**：v2.x 里它是 H03/M01 主闸，v3.0 里它是**全部视觉判定的确定性核心**——灰区仲裁、开放行为兜底都靠它；
- 形态：小 CNN（MobileNetV3 级 <10MB），多分类（Normal/吸烟/打电话/挥手/鼓掌/投掷/握手中选 5–8 个可展示类 + H03/M01），输入环形缓冲 person crop；
- 数据：复用 A3 的 M01 1502 样本 + 现有伪标签 + 为演示新类补采/蒸馏少量样本；
- **这就是把"开放词汇看图判定"从 VLM 悬崖搬到确定性小模型的落地件**——毫秒级、每帧可跑、可复现、演示不翻车。

### 4.3 语言交互层 @ 文本 LLM（算法主体的新主力）
- 后端：Qwen2.5-1.5B 纯文本 INT4（llama.cpp CANN / MindIE / MindSpore 择一），OpenAI 兼容端点，`vlm_client`/消费方零改动；
- 承接任务（全是语言侧，"差一点照样好看"）：
  - **一句话布控解析**：中文指令 → 规则结构（闭集映射到 11 类 / crop 演示类；开放描述交确定性层兜底）；
  - **感知事实 → 自然语言旁白**：跟踪器/行为标签/crop 判定/时间戳 → 文本 LLM 合成"该人员近 90 秒三次接近围栏，当前判定徘徊"——**点谁说谁的语言底座，不需要多模态**；
  - **场景记忆问答**：SceneNarrator/SceneIndex 检索 → 答问合成；
- **不再承担**：细粒度视觉判定、开放词汇看图（那些交 crop 层）。

### 4.4 可解释可视化层（fancy 的最高浓度，纯算法+前端）
- **复核链路字幕流**：把三级决策 + crop 仲裁 + 翻案逻辑做成屏上实时字幕——"PC 判 0.61 徘徊 → crop 确认 → 采纳 / 改判"。**评委第一次能"看见"边缘 AI 的认知过程**，是本作品最强记忆点，且不依赖任何硬件；
- 感知叠加：检测框/骨骼/轨迹实时渲染（前端已有组件）；
- 底牌角标：fps/内存/NPU 占用/`npu-smi` 板级功耗（**功耗证据不再需要 INA226 电路，npu-smi 直出**）；
- 数据通道：`FrameResult` 已有的 metrics/vlm_review 字段 + MQTT 遥测上行。

### 4.5 服务与部署（全同机）
- 无 Docker：systemd `csa-engine`（感知+语言+服务）；`Restart=always`；
- MQTT：本机 Mosquitto，`csa/{box}/event|status|rule/set`（遥测上行/规则下行/LWT）——**保留 MQTT 是赛题对"物联网通信协议运用"的明确评分点，不能砍**；
- 存储：results 轮转（演示用，非 7×24）。

## 5. 内存预算（算法主体版，文本 LLM）

| 组件 | 预估 |
|---|---|
| OS + CANN 驱动/运行时 | ~1.5GB |
| 感知 OM（YOLOv8n+ViTPose）@NPU | ~0.8GB |
| Python 引擎 + VDEC 帧缓冲 + FastAPI + Mosquitto | ~1.2GB |
| 文本 LLM Qwen2.5-1.5B INT4 常驻 + KV(2k) | ~1.2GB |
| Crop 多分类器 + bge-small + BM25 | ~0.5GB |
| **合计 / 4GB 版** | **~5.2GB → 4GB 偏紧，8GB 从容** |
| **合计 / 8GB 版** | **~5.2GB / 留 ~2.8GB（可挂 stretch 多模态）** |

> 4GB 版：文本 LLM 常驻仍偏紧，用"文本模型更小的 Qwen2.5-0.5B 或空闲卸载"轻松解决——量级远小于 v2.1 多模态腾内存的苦战。8GB 版：余量足够做**可选 stretch——挂 VL-2B 交替档**，把开放词汇升级回真·看图判定（成功加分，失败零损伤）。

## 8. 风险与对策（算法主体版）

| # | 风险 | 概率 | 对策 |
|---|---|---|---|
| 1 | **VDEC 硬解不通 → 单盒不成立** | 中（成败线）| M0 G2 第一验证；退双盒（附录）|

## 9. 价值排序的诚实交底（一次说清）

砍掉嵌入式执行硬件，本赛道评分的取舍是：
- **损失**：完整性 10% 的"实物外壳/PCB"分、创新性 25% 中"硬件形态/传感组合"那条、技术性里"软硬件设计复杂度"的硬件半边；
- **保住/增益**：技术性 35% 的"边缘 AI 部署优化（内存/速度/功耗）"半边完全保住（OM+VDEC+单盒+文本 LLM+npu-smi 功耗）；创新性靠**算法创新**（零标注蒸馏、一句话布控、可解释复核链路、场景记忆问答）拉满；
- **合规底线**：摄像头=数据采集、MQTT=网络通信、单盒=边缘 AI 推理，三能力齐，仍是合法 AIoT 作品，只是轻壳。

这是"算法主体"价值排序下的最优交换。若后续想补完整性分，附录双盒里的 INA226/PIR 传感链是现成的低成本加装项，随时可加回，不必现在做。
